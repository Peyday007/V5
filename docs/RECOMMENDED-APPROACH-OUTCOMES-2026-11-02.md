# Recommended Approach — the six changes, settled on current production

**Date:** 2026-11-02. **Base:** `production` at `60c9a1e`.

The 2026-10-15 assessment (on the unmerged branch
`claude/assess-recommended-approach-b68v80`, commit `274995b6`) ranked six
"smallest justified changes" and implemented #1 and #2 on that branch only.
Production moved a long way since (§65–§83), so each one was re-checked
against current code rather than cherry-picked. Every "fails without it" below
was verified by running the new test against production's unchanged `server/`.

| # | Change | Outcome | Where | Test |
|---|---|---|---|---|
| 1 | Decline Brain's own readying and contacting when `price − exposure` loses money | **Already covered** by production (`losesMoneyOnItsFigures`, shipped separately). Nothing drove that path in a test, so one was added. Production uses a strict `<`, as `tier.ts` and `jobPipeline.ts` do; break-even was left as it is so the three readers agree. | `server/services/cash/operate.ts:395`, `:1090`, `:1109` | `tests/cashProposal.test.ts` — "neither readies nor contacts for a complete card whose own figures lose money" (passes on production) |
| 2 | A repair after an attempt that read nothing names the reading failure | **Incident covered, residual implemented.** The ENOTFOUND case now reaches the cause-keyed unreadable branch (`blockCause` SOURCE_ACCESS). An attempt that accepted nothing for any *other* cause, such as a faulted work item, was still told "corroboration is missing". It now names the recorded failure. | `server/services/research/repair.ts` (`missingEvidence`) | `tests/repair.test.ts` — "names the recorded failure when nothing was accepted…" (fails without) |
| 3 | Ask whether Brain can deliver before a dive | **Implemented.** `whyNotDiving` reads `deliveryReading` last and refuses with `CANNOT_DELIVER` only on a known bar: physical work, or a `PRODUCE_*` capability whose proof has not passed (§67). An unrecorded delivery, an unallocated task, an unreadable capability or a missing integration a person can perform by hand (such as sending the email) is a blank, so it still dives (invariant 39). | `answers.ts` (`DeliveryBar`, `UNDELIVERABLE`), `validation.ts` (`whyNotDiving`), `standing.ts`, `standingSurface.ts` | `tests/cashKernelProgress.test.ts` — "spends no deep dive on an opening whose delivery needs physical work, and still dives a blank one" (fails without) |
| 4 | Read price only from buyer-side signals | **Implemented.** `proposeTerms` reads figures from the signal only when its family is `BUYER_REQUEST`, or when no signal is declared (captured by hand). The family table moved from `duplicates.ts` to `domain/opportunitySignals.ts` so identity and price read one table. | `answers.ts` (`proposeTerms`), `domain/opportunitySignals.ts` (`OPENING_FAMILY`) | `tests/cashProposal.test.ts` — "never reads a seller's own fee schedule…" (fails without) |
| 5 | A documented "nothing is bought" answers `directCosts`; ask that lane by name in round two | **First half already covered:** `ABSENCE_IS_NOT_AN_ANSWER` holds only `payer` (`validation.ts`), tested by `tests/cashDiveAnswers.test.ts` "a documented absence in the cost or price lane is still an answer". **Second half implemented:** a second full dive in an epoch asks only the still-open fields by lane, says a NEGATIVE_EXISTENCE claim answers, and restates the payer, because the gate requires that lane. | `validation.ts` (`validationQuestion`, `LANE_FOR_FIELD`, `startValidations`) | `tests/validationEnvelopeScreen.test.ts` — "a second full dive asks what the first left open, by lane" (fails without; also checked against the envelope) |
| 6 | Prefer a different surface for a repair after SOURCE_ACCESS | **Obsolete as stated, replaced by a smaller change.** `brain_fetch_source` (#368) has Brain open the public page itself, so which surface runs the repair no longer decides whether the host can be read. Routing a repair to another surface would change nothing. The repair text still said "do not retry the same addresses", which steered the worker away from the one route that now works. It now says to read those addresses through `brain_fetch_source` first, and to look for another route only if Brain cannot read them either. | `repair.ts` (unreadable branch) | `tests/researchUnreadableRepair.test.ts` — "is chosen by the stored cause…" (fails without) |
